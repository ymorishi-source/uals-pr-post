# 言語系学会連合 広報支援アプリ

加盟学会（38 学会）のウェブサイトを自動で巡回して更新を検知し、AI（OpenAI）が告知を要約・分類、X（旧 Twitter）向けの投稿文を作成するまでを 1 つの画面で行うウェブアプリです。
これまで「編集委員が各サイトを目視 → スプレッドシートに記入 → 管理委員が X に投稿」と手作業だった流れを置き換えます。

## 画面構成

| 画面 | 役割 |
|---|---|
| ホーム | 新着・投稿待ち・今月の投稿数・取得エラーの集計。「全学会を巡回する」ボタンと進捗表示 |
| 更新情報 | 従来のスプレッドシートに相当。新着 → 採用／見送り → 投稿文生成 → 投稿済み、を 1 件ずつ処理。検索・学会別絞り込み・CSV 書き出し |
| 加盟学会 | 監視対象の学会一覧（uals.net の会員学会リンクから初期登録済み）。URL・RSS・担当者の編集、1 学会だけの巡回、現在掲載中の告知の一括抽出 |
| 巡回履歴 | 巡回ごとの学会別結果（新着／変化なし／エラー） |
| 設定 | OpenAI API キー・モデル、投稿文のスタイル指示、ハッシュタグ、文字数上限、担当者名、毎日の自動巡回 |

## セットアップ

必要なもの: Node.js 20.12 以上（動作確認は v22）。

```bash
cd 言語系学会連合広報
npm install
npm start
```

ブラウザで http://localhost:3000 を開きます。初回起動時に加盟学会 38 件が `data/db.json` に登録されます。

OpenAI API キーは「設定」画面で保存するか、`.env.example` を `.env` にコピーして `OPENAI_API_KEY` に記入します。
キーがなくても巡回・差分検知・CSV 書き出し・手動入力は使えます（AI による抽出・投稿文生成だけが無効）。

## 基本的な使い方

1. ホームの「全学会を巡回する」を押す。初回は各サイトの現在の内容を基準として保存するだけで、RSS がある学会については直近 30 日の記事を取り込みます。
2. 2 回目以降の巡回では、前回からの追加テキストだけを AI に渡し、大会・研究会・発表募集・刊行などの告知を抽出して「更新情報」に新着として登録します。
3. 「更新情報」で新着を開き、内容を確認して「採用」か「見送り」を選びます。
4. 採用した件で「AI で生成」を押すと X 投稿文ができます。文字数は X の規則（全角 2・半角 1・URL 23、上限 280）でカウント表示されます。手直しして「コピー」または「X の投稿画面を開く」で投稿し、「投稿済みにする」で記録します。
5. 必要なら「uals.net お知らせ用の文案」で、uals.net のお知らせ記事（タイトル＋箇条書き）の下書きも生成できます。
6. 複数件をまとめて整理するには、更新情報の各行左のチェックボックスで選択し、上部に出るバーから「削除」「投稿済みにする」「見送り」を選びます。@uals_pr ですでに配信済みの情報を片付けるときに使います。
7. 「加盟学会」の各行メニューから、サイトに今載っている告知を AI で一括抽出することもできます（初期の立ち上げや取りこぼしの確認に便利です）。

巡回で検知できないサイト（巡回履歴でエラーになる学会）は、従来どおり目視で確認し、「手動で追加」から URL を入れれば AI がそのページを読んで登録します。

## 仕組み（概要）

- `lib/fetcher.js` ページ取得。Shift_JIS・EUC-JP などの文字コード自動判定、フレーム構造の古いサイトの子フレーム追跡、RSS/Atom の解析と自動検出。
- `lib/crawler.js` 前回スナップショット（`data/snapshots/`）との行単位の差分を取り、追加分だけを AI に渡す。重複は URL と件名で除外。4 学会ずつ並列で巡回（38 学会で 10 秒前後）。
- `lib/ai.js` OpenAI Chat Completions（JSON Schema 出力）。抽出・X 投稿文・お知らせ文案。既定モデルは `gpt-5-mini`（設定で変更可）。
- `server.js` Express API と静的ファイル配信。`data/db.json` に学会・更新情報・巡回履歴・設定を保存。
- `public/` フロントエンド（Material Design 3 のトークンに沿った自前 CSS、依存ライブラリなし）。

## X 投稿文の書式

既定の生成スタイルは @uals_pr の既存投稿に合わせてあります（1 行目【学会名】、空行、件名「〜のお知らせ」、「日時：」「場所：」などの項目行、空行、URL。ハッシュタグなし）。「設定」画面の「X 投稿文のスタイル」で変更できます。

## 複数人で使う場合

- 1 台の PC（研究室のサーバーなど）で `npm start` しておき、同じネットワークから `http://<そのPCのIP>:3000` で開けます。
- コードは GitHub に置けますが、GitHub Pages のような静的ホスティングでは動きません（Node.js のサーバーが必要です）。GitHub からデプロイできる Render・Railway・Fly.io や、契約サーバー（さくら VPS など）で `npm install && npm start` を実行してください。
- インターネットに公開する場合は `.env` の `APP_PASSWORD` に共通パスワードを設定してください（Basic 認証がかかります）。Render や Railway などでも動きますが、`data/` が消えない永続ディスクが必要です。
- 毎日の自動巡回は「設定」で有効化できます（サーバーが起動している間だけ動きます）。

## GitHub への公開とサーバーへの配置

リポジトリには `data/`（更新情報・巡回結果・設定）と `.env`（API キー）は含まれません（`.gitignore` で除外済み）。API キーは必ず `.env` か「設定」画面に入れ、コードに書かないでください。

GitHub で公開する手順:

1. https://github.com/new で新しいリポジトリを作る（名前は例: `uals-pr-assistant`）。README などは追加しない。
2. 作成後に表示される URL を使って、このフォルダで次を実行する。

```bash
cd ~/Desktop/言語系学会連合広報
git remote add origin https://github.com/<ユーザー名>/uals-pr-assistant.git
git push -u origin main
```

サーバーに配置する場合は、Node.js 22 を入れて `git clone` → `npm install` → `.env` を作成 → `npm start`（常駐には pm2 や systemd を使う）。Docker が使える環境では同梱の `Dockerfile` で動きます（`data/` をボリュームとして永続化すること）。

## 既知の制約

- 日本方言研究会（dialectology-jp.org）はサーバー証明書のチェーン不備で自動取得できません（ブラウザでは閲覧可）。巡回ではエラー表示になるので手動確認が必要です。
- X への投稿は「投稿画面を開く」方式です（X API での自動投稿は別途 API 契約が必要なため未実装）。
- 1 回の巡回で AI が読むのは追加分のみのため、サイトを全面改修した学会は初回扱い（基準再取得）になります。

```

lib/ai.js            OpenAI 連携
lib/text.js          X 文字数カウントなど
lib/seed.js          加盟学会の初期データ
public/              フロントエンド
scripts/check-fetch.js  取得テスト用 CLI（node scripts/check-fetch.js <URL> [--feed]）
data/                実行時データ（git 管理外）
```
